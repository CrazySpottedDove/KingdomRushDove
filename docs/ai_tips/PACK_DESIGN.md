# 插件整合包（Pack）功能设计 v3（简化版）

> 状态：v3，已按新一轮简化决策收敛（取代 v2.x 的本地包管理/开发者上传等设定）。
> 适用范围：游戏端（本仓库插件管理器）＋ 网页插件商店（父项目 frontend）＋ 服务器（父项目 src）。

## 1. 概念（最终形态）

| 概念 | 归属 | 说明 |
|---|---|---|
| 插件 Plugin | 商店/本地 | 现有体系，`plugins/<entry>/` |
| 整合包 Pack | **仅网页端/服务器** | 作者在网页端创建与维护的清单（`packs/<entry>/pack.lua` + 可选 `README.md`，服务器契约不变）。**没有"本地整合包"概念** |
| 本地分组 Group | **仅游戏端本地** | 玩家自建命名集合：批量启用/禁用一组插件。可视为"未发布的私有清单"，但**与商店整合包解耦** |
| 成员插件 | — | 本地分组引用的本地插件 entry；插件存储位置不变 |

## 2. 职责边界

### 2.1 网页端（作者）
- 创建 / 编辑整合包：名称、版本、简介、README、**成员增删（网页端完成）**、封面；删除。
- 下载物为 `<entry>.zip`（pack.lua + 可选 README.md）。
- 无本地概念字段。

### 2.2 游戏端
1. **商店整合包安装**（保留游戏内"整合包商店"浏览与详情）：
   - 动作 = 下载清单 → 解析成员 → **同步插件**：本地缺失 → 安装；本地已有且商店版本不同 → 自动更新（保留本地配置与 enabled）；版本一致 → 不动。
   - **不写任何本地包记录**，不缓存 README，不做包级卸载/更新/移除记录（作者在网页端维护成员）。
   - 商店包行的卸载/更新/移除记录等本地管理类动作一律移除；行动作 = 详情、安装/重新同步。
2. **本地分组界面**（替代原"整合包"本地分页；按钮文案为"分组"）：
   - 仅本地功能：创建（自动生成不会冲突的 entry）/重命名/编辑成员/删除分组。
   - 整组批量动作：启用整组 / 停用整组（语义：把组内成员的 enabled 置 true/false；**不新增状态机**，仍走现有"应用/重启"收敛）。
   - 组状态展示：由成员 enabled 聚合为 全部启用/部分启用 n/m/已停用（纯展示）。
3. 与插件体系一致约束：运行时只认 `plugins/<entry>/config.lua.enabled`；分组文件不参与加载；崩溃自动禁用天然反映为"部分启用"。

### 2.3 不做（明确取消/不实现）
- 游戏端创建/编辑/管理"商店整合包"；本地包记录（packs 记录化管理）；包级卸载（连带删插件）、更新记录、移除记录。
- 游戏内开发者"上传本地分组为整合包"。
- 本地分组导出/导入 UI。
- 一个插件同时属于多个分组（见 §3 排他性）。

## 3. 本地分组（游戏端）详细规则

### 3.1 创建/命名
- 弹窗输入名称（1~40 字符，重名校验：与其他分组名不同）。
- entry 自动生成：`group_<时间戳>`，如冲突则追加序号（保证不与任何分组/插件 entry 冲突）。

### 3.2 编辑界面（两栏 + 搜索 + 排他）
- 布局：左栏"可加入的插件"，右栏"已在分组中的插件"。
- **排他性**：已属于其它分组的插件不得再加入本分组（不出现在左栏可选列表；若直接出现在左侧则禁用并标注原因）。
- 搜索框：按本地插件名/entry 过滤左栏候选（右栏为组内成员，数量少可不做搜索或同样支持）。
- **分组分类 tag**：编辑器可给分组设置分类（单行 chips，与插件分类体系一致，缺省视为 other）；分组列表行展示该 tag，并用顶部"分类"下拉按 tag 筛选（本地插件/整合包商店/本地分组三类视图共用同一分类下拉）。
- 左栏行 = 插件名/entry + "加入"动作；右栏行 = 插件名/entry + "移除"动作。
- 底部按钮：**取消居左、保存居右**（不再都挤右侧）。
- 编辑保存后：成员表替换为该分组记录；其它分组成员表不受影响（排他性由保存校验兜底）。

### 3.3 批量动作语义
- 启用整组：组内每个**本地存在**成员的 enabled=true（缺失成员跳过并提示）；停用整组同理置 false。
- 因排他性，组间无交叉引用，无需跨组跳过规则。
- 只改内存 + `_unsaved_changes`，点"应用"统一落盘/热重载/重启（与单插件开关一致）。

### 3.4 删除分组
- 二次确认；仅删除分组文件，**不触碰任何插件**（组不具备插件所有权）。

### 3.5 存储（实现细节）
- 存档根 `packs/<entry>/pack.lua` 保存分组（**v4 精简 schema**）：`{ entry, name, members = { "插件entry", ... }, category = "gameplay"? }`——`members` 为**有序数组（成员唯一事实源）**；`category` 为可选**分组分类 tag**（与插件同分类体系，缺省视为 other）。不再写入 `by/version/state/desc/members_order` 等冗余/遗留字段。
- 读取兼容旧格式（`members` 字典 + `members_order`，或含 `by/desc/version` 的历史文件）：旧字段被忽略；编辑器保存时按 v4 schema 重写（旧文件非空 `desc` 会保留展示，可选）。
- 纯本地文件，玩家手删/损坏 → 容错：损坏项显示"移除记录"式清理入口或直接忽略（按实现简单程度）。

## 4. 游戏端 UI 结构（相对 v2.x 的收敛）

- 顶部作用域切换（本地模式）：`插件` / `分组`（原"整合包"按钮文案改"分组"）。
- 商店模式作用域：`插件商店` / `整合包商店`（保留，动作按 §2.2-1）。
- 移除/不再调用的本地包管理 UI：本地"已装商店包"行、包级状态（可更新/已下架）、卸载/移除记录/更新记录按钮、README 本地缓存与本地详情读档逻辑等。
- 保留但只服务本地分组：分组行的"详情/启用/停用/编辑/删除"。

## 5. 跨端契约要点（服务器不变）

- 服务器 `/packs/*`（list/entries/detail/download zip/upload/create/delete/cover/readme）沿用；整合包带 **下载量统计**（/packs/download 访问 +1，list 排序 newest/downloads/hot 与插件一致）并新增 **category（与插件同分类体系）**，list/create 支持分类（老库启动自动补列）。网页端提供分类筛选与展示，游戏端整合包商店提供分类筛选。
- 游戏端仅调用：`/packs/list`（可选浏览）、`/packs/download/<entry>.zip`（安装）、`/packs/{entry}`（详情 readme）、批量 `POST /plugins/entries`（成员版本比对）。

## 6. 验收（游戏端人工 QA）

1. 商店→整合包：安装某包 → 缺失成员自动装齐、已装但旧的成员自动更新、最新成员不动；**本地不新增包记录/分组**；再次点安装 = 重新同步。
2. 本地→分组：新建（重名拦截、自动 entry）；两栏编辑可搜索、排他生效（已在别的组的插件不可再加入）；加入/移除即时生效；保存/取消左右分布。
3. 启用整组/停用整组 → 点"应用"后成员开关按预期变化（含运行中→重启）。
4. 删除分组二次确认且不影响插件；损坏分组文件容错。
