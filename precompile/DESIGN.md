# 预编译重构设计

> 本文档只在开发分支维护。`makefiles/master.sh` 投影 master 时会把
> `precompile/DESIGN.md` 排除，不进入发布分支。

## 1. 背景

当前 `precompile/` 的实现方式是：

- 在 `precompile/templates/*.lua` 中手写真实脚本的副本；
- 用 `constif/constfor/constvar/@constif` 等行级指令描述“按实体配置删分支”；
- 游戏启动时把这些模板字符串编译成 Lua 源码，再 `load()`。

它带来三个问题：

1. **功能弱**：模板是行级文本替换，不是 Lua；模板形参没有真正绑定，嵌套模板靠自由变量，`constfor` 只支持数字循环，被调用的 helper 函数无法纳入特化。
2. **debug 困难**：生成代码没有源映射，`load` 没有 chunkname，错误只能靠“生成行前几十个字符去模板里模糊匹配”回推；运行时错误不在保护范围；现有测试已经失效。
3. **速度慢**：每个实体启动时都要重新遍历指令、求值、拼源码、重命名、改 return、`load`；全局 `cf_counter` 让相同配置生成不同代码，代码字符串缓存基本失效。

## 2. 目标

1. 删除 `precompile/templates/`，真实脚本只维护一份。
2. 构建期读取真实 Lua 源码，按实体配置生成优化函数。
3. 游戏启动只加载生成结果，不再解析模板、不再做字符串代码生成。
4. `register_t_hot` / `register_t_tmp` / `precompile_hot` 外部行为不变；热模板运行时编译，**不做临时模板缓存**。
5. 构建期能给出真实文件行号、残留分支清单、无法定位源码的函数清单。

### 非目标（第一期）

- 不做 helper 内联，只生成 helper 的专用版本，保留函数边界和 `return/yield/goto` 语义。
- 不消除运行时状态分支（血量、目标、寻路状态等）。
- 不支持无法从源码定位的函数（例如运行时 `load` 出来的函数）；这类保留原调用并报告。
- 不做临时模板缓存。

## 3. 基线

本机 LuaJIT，使用 `scripts/ci/love_stub.lua` 无窗口加载：

| 项目 | 数值 |
|---|---|
| `E:load()` 加载实体模板 | 4528 个，约 226 ms |
| 当前预编译命中函数 | 1814 个 |
| 当前 `E:precompile()` 耗时 | 约 67.6 ms |
| 当前生成源码总量 | 约 2.4 MB |

2.4 MB 文本生成物与现有 `kr1/data/game_animations.bin`（约 1.2 MB）同量级，按编译产物提交。

## 5. 构建流程

### 5.1 加载实体数据

新增无预编译加载路径，避免构建时先触发运行时编译：

```lua
-- all/entity_db.lua
function entity_db:load_for_build()
    self.loaded = true
    self:load()
end
```

`scripts/precompile.lua` 使用 `scripts/ci/love_stub.lua` 打桩，然后 `E:load_for_build()`。

### 5.2 找到每个实体要处理的函数

`precompile/specs.lua` 用数据表替代 `interface.lua` 里写死的 if/elseif：

```lua
return {
    {
        key = "insert",
        source = function() return scripts.enemy_basic.insert end,
        when = function(e) return e.enemy end,
        group = "enemies",
    },
    {
        key = "update",
        source = function() return scripts.enemy_mixed.update end,
        when = function(e) return e.enemy and (e.melee or e.ranged) end,
        group = "enemies",
        context = true,        -- 对应 main_script.type = 1
    },
    -- bullet / soldier / modifier / aura 同理
}
```

构建时遍历 `E.entities`，对每个 spec 检查 `when(e)` 和 `m[spec.key] == source`，得到 `(entity, spec)` 列表。

### 5.3 找到函数对应的源码

对每个原函数：

```lua
local info = debug.getinfo(fn, "S")
-- info.source      = "@./all/scripts.lua"
-- info.linedefined = 864
```

读取该文件，解析成语法结构，按函数定义起始行建立索引。已验证 `scripts.enemy_basic.insert` 定位到 `all/scripts.lua:864`。

被调用函数同理：从调用表达式 `SU.y_enemy_walk_step_default(...)` 的全局路径在构建环境里查到函数对象，再用 `debug.getinfo` 定位源码。解析不到的情况记录为“未优化调用”，构建不失败。

### 5.4 特化

对每个 `(entity, spec)`：

1. 建立上下文：`this = 实体配置常量`，`store = 运行时未知`。
2. 按语句执行，维护局部变量的抽象值。
3. 遇到 `if`：
   - 条件能算出常量 → 只保留命中的分支；
   - 条件依赖 `this` 但算不出 → 保留运行时 `if`，记入“残留分支”；
   - 条件来自 `store/target/health` → 保留，记入“运行时分支”。
4. 遇到数字 `for` 且上下界都是常量：
   - 展开，每次迭代套 `do ... end`，避免局部变量数量超限；
   - 含 `break`、`goto`、`yield` 或超过展开上限（先定 256）时不展开，保留循环并报告。
5. 遇到 `SU.xxx(...)` / `U.xxx(...)` 这类可定位的调用：
   - 把实参的抽象值绑定到 helper 参数；
   - 生成 helper 专用版本；
   - 如果这个 helper 没有任何分支被折叠，就保留原调用，不生成冗余副本。
6. 其他调用：保留原调用。

第一版假设：函数执行期间 `this` 的模板字段不被改写（和当前预编译的假设一致）。如果检测到对 `this.x` 的赋值，后续依赖该路径的条件不再折叠。

### 5.5 生成

- 命名稳定：`__pc_<spec>_<entity>`、`__pc_h<N>`。
- 每个生成文件头写 `-- Generated by scripts/precompile.lua; do not edit.`
- 相同生成代码先按 `(type, 源码)` 去重，统一写入 `generated/shared.lua`；分组文件只保存 `shared[id]` 引用。同一实体在不同文件里有不同函数时由 loader 合并。
- 每个文件返回：

```lua
return {
    enemy_goblin = {
        insert = function(this, store) ... end,
        update = function(this, store) ... end,
        type = 0,
    },
}
```

- 生成后构建期 `load` 每个文件校验语法；`check` 模式在内存生成并与现有文件比较，不一致返回非 0。

## 6. 运行时加载与热注册

### 6.1 `interface.lua` 新职责

```lua
function M:compile(e)
    local generated = self.generated[e.template_name]
    if generated then
        self:apply_generated(e, generated)
        return
    end
    self:runtime_compile(e)
end
```

`apply_generated` 对每个函数和 `type` 走 `set_and_backup`，保证父模板的备份里仍是原始脚本。

`runtime_compile` 懒加载 `stage/specialize.lua`，按 `specs.lua` 匹配原始函数并编译；找不到源码就保留原脚本并记录一次警告。

### 6.2 `register_t_hot` 处理

`all/entity_db.lua` 里改为显式传 base：

```lua
if t.main_script then
    compiler:restore_main_script(t, base)
end
t.template_name = name
```

`restore_main_script(e, base)` 用 `base` 查 `main_script_backup`，不再依赖“改名之前调用”这个隐式时序。`register_t_tmp` 同样处理。

- 构建期生成的函数在启动时也通过 `set_and_backup` 应用，所以 `main_script_backup[base]` 里有原始函数和原始 `type`。
- 热注册复制父模板 → 恢复原始函数和 `type` → `precompile_hot()` 按新配置重新编译。
- 临时模板不进 `entities_backup`；每次关卡加载重新注册、重新编译，**不加缓存**。
- `entity_db:hot_load` 已无调用点，直接删除。
- `register_t` 不处理，它只用于启动加载阶段。

### 6.3 插件

插件新增实体继续走 `register_t_hot` / `register_t_tmp`，运行时编译兜底。构建期不加载插件模板；插件想在启动时零编译，需要后续单独提供“插件构建产物”机制，本期不做。

## 7. 诊断

### 命令

```sh
make precompile          # 生成
make precompile_check    # 检查生成物是否最新且可编译
luajit scripts/precompile.lua dump <entity> <key>
luajit scripts/precompile.lua explain <entity> <key>
```

### `check` 输出

1. 源码语法错误：`all/scripts.lua:864:17: ...` + 附近代码。
2. 生成代码 `load` 失败：映射回源文件行号。
3. 残留分支报告：

```text
enemy_mixed.update @ enemy_goblin
  folded 47, unrolled 3
  runtime:  this.health.dead                 all/scripts.lua:1001
  unresolved:
    this.motion.forced_waypoint              all/script_utils.lua:3425  (helper 未定位)
```

4. 无法定位源码的函数清单。
5. `--strict` 下“配置相关但没折叠”的分支视为错误。

### 运行时错误

生成文件本身可读。错误栈显示 `precompile/generated/shared.lua:123`；构建期错误仍有完整源码行号，运行时可结合 `dump` 定位。精确到语句的源映射留给后续可选功能。

## 8. 构建与打包集成

### Makefile

新增：

```make
precompile:
	luajit scripts/precompile.lua build

precompile_check:
	luajit scripts/precompile.lua check
```

挂到：

- `all`、`debug`：先 `precompile`，再 `sync`，保证 Windows 端拿到最新产物。
- `windows`、`linux`、`android`、`installer`、各 `*_quick`：打包前 `precompile_check`，产物过期直接失败。
- `add`：`precompile` 后再 `git add .`，生成物和源码一起提交。

### 生成物策略

- `precompile/generated/` 提交进 git，不进 `.gitignore`。
- 更新只在脚本/实体配置变化时发生。
- `make precompile_check` 在 CI 里跑，防止忘记重新生成。
- `precompile/generated/` 同时从 `dlfmt_task.json` 的 format/compress 任务里排除，保证生成物字节稳定、`precompile_check` 有意义，也方便直接阅读生成代码。
- `master.sh` 的“仅源码剔除”逻辑不能把 `precompile/generated/` 算进去。
- `precompile/DESIGN.md` 由 `master.sh` 单独排除，不进入 master。

## 9. 测试与验收

### 单元测试

- 词法/语法：覆盖项目实际用到的 Lua 写法（`if/elseif/else`、数字/泛型 `for`、`while`、`repeat`、`goto/label`、`local function`、方法调用、多返回值、varargs、长字符串/长注释）。
- 特化：构造小实体，断言 `if` 被折叠、`for` 展开、残留分支分类正确。
- 生成代码：可 `load`、无重复函数、无空行、无注释。

### 行为对照

对每个 spec 选若干代表性实体：

- 运行原函数和生成函数，比较：
  - 返回值；
  - 实体可观测字段（`pos`、`health`、`context`、`motion` 等）；
  - 入队/移除的实体、伤害队列；
  - 协程 `yield` 次数与顺序。
- 用现有 `precompile/tests/harness.lua` 的思路搭 mock store；失效的旧测试直接重写，不再保留打印 `FAIL` 但整体通过的测试。

- `make precompile_check`：生成物最新且可 `load`。
- golden hash：所有实体生成结果哈希，变更必须显式接受。
- `make check-text` 现有检查继续通过。

- 运行时基准：`bench_enemy_mixed` / `bench_aura` 改造成“原函数 vs 生成函数”；验收线先定 ±5%，超出需解释。

## 11. 风险与回退

| 风险 | 应对 |
|---|---|
| 自写 Lua parser 不完整 | 先支持项目实际语法；解析失败只影响对应函数，保留原调用并报告，不让构建崩溃 |
| helper 是局部函数/动态调用，定位不到 | 第一期只处理 `SU/U/LU` 等全局表路径；报告列出来，后续再扩展 |
| 特化改变行为 | 每个 spec 行为对照 + golden；出问题只回退该 spec 到原脚本 |
| 生成物过期 | `make all/debug` 自动生成；`precompile_check` 在打包/CI 失败 |
| 生成物体积/加载时间 | 按 spec 分文件；先实测，超过预算再拆分或按关卡懒加载 |
| 插件/热模板没有优化 | 运行时编译兜底；不缓存，保证配置变化一定重新生成 |

## 14. 状态机与脚本类型（2026-10-25）

状态机不再放在模板里，而是和协程版并存的两份**真实 Lua 函数**：

- 协程版保留原函数名，例如 `scripts.arrow.update`，供插件/热加载/运行时兜底。
- 状态机版使用 `_sm` 后缀，例如 `scripts.arrow.update_sm`。
- `specs.lua` 区分匹配身份和编译源码：

```lua
{
    key = "update",
    source = scripts.arrow.update,
    compile_source = scripts.arrow.update_sm,
    state_machine = true,
}
```

构建期用 `compile_source` 生成函数，生成条目带 `type = 1`；实体模板仍匹配 `source`。

### 脚本类型校正

`precompile/interface.lua` 维护 `script_types` 弱表：

- `source` 默认按协程脚本标记（`0`）；
- `_sm` / 生成的状态机函数标记 `1`；
- 生成的协程函数标记 `0`。

`main_script:on_insert` 调用 `ensure_entity_type(e)`：

- 已知函数按标记设置 `main_script.type`；
- 未知函数默认按协程处理（`0`），并创建 `context`，因此插件自定义状态机也能在协程路径下每帧执行；
- 函数变化时清理旧的 `s.co`，避免继续跑旧协程。

更新队列额外记录 `_pc_queue_type`，移除时按实际入队类型处理；`on_update` 派发前检查 `s.update` 是否变化，变化时重新校正类型。这样即使插件继承状态机模板后重赋协程脚本、甚至已插入后再换函数，也不会把协程当状态机直接调用。

## 15. 常量白名单与表达式折叠

编译期常量路径统一放在 `precompile/whitelists.lua`，按 family 维护：

- `arrow.insert` 和 `arrow.update` 共用 `M.arrow`；
- `bomb` / `bolt` / `mod_dps` / `aura_*` 各自一份；
- `enemies` / `soldiers` 各自一份；
- 不再有全局 `SAFE_ROOTS` / `SAFE_PATHS`；`value.lua` 只负责 Value 模型和路径拼接。

特化器还支持表达式级常量折叠：`not true`、`true and x`、`false or x` 等会直接化简，因此 `if not b.straight_forward_distance and context.state == 2 then` 会变成 `if context.state == 2 then`。

求值器同时支持 `band` / `bor` / `bnot` 这类纯函数的编译期求值，所以带 family 白名单的 `band(a.vis_bans, F_ENEMY) ~= 0` 会按实体配置直接折叠成 `true` / `false`，不会把整段目标筛选分支都留在运行时。
